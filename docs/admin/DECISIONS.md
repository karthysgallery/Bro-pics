# BroPics Admin Panel: Architectural Decisions Record (ADR)

## ADR-001: Frame Border and Mat Physical vs Printed
- **Decision:** Physical frame moulding with printed matting & photos.
- **Rationale:** The high-resolution 300 DPI print output generated by the Cloud Run Sharp service renders the customized photo layout and any printed mat border/text directly onto photo media; the physical frame moulding is assembled around the print.

## ADR-002: Five-Tier RBAC Roles & Hierarchy
- **Decision:** Five canonical roles:
  1. `super_admin`: Full system control, dangerous operations, team management.
  2. `admin`: Business owner operations (catalogue, orders, refunds, settings, analytics).
  3. `staff`: Workshop and fulfillment execution (orders, QC, shipments, returns, stock adjustments).
  4. `catalogue_manager`: Products, variants, categories, collections, templates, inventory.
  5. `marketing_manager` (formerly `content_manager`): Coupons, reviews moderation, storefront merchandising, announcement bar, analytics.
- **Backwards Compatibility:** Legacy `content_manager` custom claims map cleanly to `marketing_manager` permissions so existing sessions are not disrupted.

## ADR-003: Courier Integration & AWB Tracking
- **Decision:** Pluggable Courier Adapter Architecture with manual AWB assignment, CSV bulk import, and dynamic tracking URL templates (`{awb}`).
- **Rationale:** Allows immediate operations with any courier service (Delhivery, BlueDart, Shiprocket, DTDC) while establishing clean adapter interfaces for automated API booking.

## ADR-004: Item-Level and Whole-Order Returns & Refunds
- **Decision:** First-class item-level data model (`returnItems[]`) supporting both single-item and whole-order returns/replacements/refunds from Day 1.
- **Rationale:** Enables granular replacement production orders and partial refunds with strict max-refundable validation.

## ADR-005: Dual-Layer Security & Data Isolation
- **Decision:**
  1. Application layer: `requirePermission(ctx, key)` enforcing Firebase ID Token claims and verifying against `staff/{uid}` mirror `disabled === false` with `checkRevoked: true`.
  2. Database layer: Firestore security rules deny all direct client-side writes to admin collections (`products`, `orders`, `staff`, `settings`, `auditLogs`, `mediaAssets`).
  3. Client bundle isolation: Admin repositories and server utilities use `server-only`. No secrets in client bundles.
